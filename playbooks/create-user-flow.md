# Skill: User Flow 작성

## 목적
분석된 요구사항을 시나리오별 User Flow로 변환한다.

## 사용하는 Agent
- Planner Agent (주 사용)
- Prototype Agent (네비게이션 연결 시 참조)

## 절차

### 1. 시나리오 분류
요구사항의 Goal을 독립적인 시나리오로 분류한다.
- 각 시나리오는 하나의 핵심 Task를 완료하는 단위이다.
- 시나리오 간 겹치는 화면이 있을 수 있다.

### 2. Happy Path 작성
각 시나리오의 이상적인 흐름을 먼저 작성한다.
- 시작점: 사용자가 처음 도달하는 곳
- 끝점: Task가 완료되는 곳
- 각 단계: [사용자 행동] → [시스템 반응]

### 3. 분기 추가
Happy Path에 분기를 추가한다.
- 조건을 명시한다 (예: "검색 결과가 0건이면")
- 각 분기의 끝점을 명시한다 (다른 화면으로 이동 또는 상태 변화)

### 4. Edge Case 경로 추가
Edge Case에 대한 대응 경로를 추가한다.
- Error 발생 시 어디로 가는가?
- Empty State에서 어떤 대안을 제시하는가?

### 5. Flow 간 연결점 표시
시나리오 간 이동 가능한 지점을 표시한다.
- 검색 결과에서 AI 추천으로 전환
- AI 추천 결과에서 검색으로 전환
- 어디서든 비교 화면으로 이동

## Output 형식
`specs/user-flow.md`에 작성:

```markdown
# User Flow

## Flow 1: [시나리오 이름]
**시작점**: [화면/진입점]
**끝점**: [완료 상태]

1. [사용자 행동] → [시스템 반응] → **[다음 화면]**
2. [사용자 행동] → [시스템 반응]
   - 조건 A: [결과] → **[화면 A]**
   - 조건 B: [결과] → **[화면 B]**
3. ...

### Edge Cases
- [상황] → [대응] → **[화면]**

---

## Flow 2: [시나리오 이름]
...

---

## Flow 간 연결
| From | To | 트리거 |
|------|----|--------|
| [화면] | [화면] | [사용자 행동] |
```

## 검증
- 모든 Flow에 시작점과 끝점이 있는가?
- 막다른 길(Dead End)이 없는가?
- Edge Case 경로가 Happy Path로 복귀할 수 있는가?
