# Skill: 프로토타입 실행 검증

## 목적
프로토타입을 **실제 브라우저에서 띄워** 동작을 확인한다.
Critic이 코드를 읽기 전에 가장 먼저 실행한다.

> 코드만 읽으면 "렌더링해봐야 아는 문제"를 놓친다.
> JS 에러로 화면이 백지여도, 소스만 보면 요구사항을 모두 충족한 것처럼 보인다.
> 종료 조건의 "주요 Interaction을 **직접 확인**할 수 있다"는 이 Playbook으로 충족된다.

## 사용하는 Agent
- Critic Agent (주 사용, 첫 번째로 실행)

## 전제
- `prototype/index.html`이 존재한다.
- `specs/user-flow.md`에 Happy Path가 정의되어 있다.

---

## 절차

### 1. 로컬 서버 기동
`file://`로 열면 일부 브라우저에서 스크립트와 `sessionStorage`가 차단된다. 반드시 HTTP로 띄운다.

```bash
cd prototype && python3 -m http.server 8000
```

검증이 끝나면 서버를 종료한다.

### 2. 브라우저로 열기
`/browse` 스킬로 `http://localhost:8000`에 접속한다.

### 3. 콘솔 에러 수집
페이지 로드 직후 콘솔을 확인한다. **에러가 1건이라도 있으면 Critical 후보다.**

| 유형 | 심각도 | 예 |
|------|--------|-----|
| JS 문법/참조 에러 | **Critical** | `Uncaught ReferenceError`, `SyntaxError` |
| 리소스 404 | **Critical** | `styles.css`, `app.js` 로드 실패 |
| 런타임 에러 | Major | 클릭 시 `undefined` 접근 |
| 경고 | Minor | deprecated API |

### 4. 화면별 스크린샷 (375px / 1440px)
`specs/screens.md`의 모든 화면을 두 뷰포트에서 캡처한다.

각 스크린샷에서 확인할 것:
- 화면이 **비어 있지 않은가** (로드 실패 시 백지)
- 레이아웃이 깨지지 않았는가 (요소 겹침, 영역 이탈)
- 375px에서 **가로 스크롤**이 발생하지 않는가
- Primary CTA가 **하나만** 보이는가 (Mobile/Desktop 중복 렌더링이 흔한 실수)
- 텍스트가 잘리거나 넘치지 않는가

### 5. Happy Path 완주
`specs/user-flow.md`의 Happy Path를 **클릭으로 끝까지 수행한다.**

각 단계에서:
- 다음 화면으로 이동하는가
- 클릭했는데 아무 반응이 없는 요소가 있는가
- 뒤로 가기가 동작하는가
- 뒤로 갔을 때 이전 선택·필터가 유지되는가 (`manage-state` 검증)

**막다른 화면(Dead End)** — 되돌아갈 수단이 없는 화면이 있으면 Critical이다.

### 6. 상태 전환 확인
Default 외의 상태를 **실제로 띄워본다.** 마크업만 있고 전환되지 않는 경우가 많다.

| 상태 | 띄우는 방법 |
|------|------------|
| Empty | 결과가 0건이 되는 필터 조합을 입력 |
| Loading | 비동기 동작 트리거 (목업 지연이 있으면 그 사이 캡처) |
| Error | 의도적으로 실패하는 입력, 또는 해당 트리거 |

전환되지 않는 상태는 **"마크업만 존재"**로 리포트에 기록한다.

## Output
`write-critique-report.md`에 전달할 실행 검증 결과:

```markdown
## 실행 검증

**서버**: http://localhost:8000 / **브라우저**: (도구명)

### 콘솔 에러
| 심각도 | 내용 | 발생 시점 |
|--------|------|----------|
| Critical | Uncaught ReferenceError: AppState is not defined | 로드 직후 |

### 화면별 렌더링
| 화면 | 375px | 1440px | 비고 |
|------|-------|--------|------|
| 홈 | OK | OK | |
| 검색 결과 | 깨짐 | OK | 375px 가로 스크롤 발생 |

### Happy Path
| 단계 | 결과 | 비고 |
|------|------|------|
| 홈 → 검색 | OK | |
| 검색 → 상세 | 실패 | 카드 클릭에 핸들러 없음 |

### 상태 전환
| 화면 | Empty | Loading | Error |
|------|-------|---------|-------|
| 검색 결과 | 전환됨 | 전환됨 | 마크업만 존재 |
```

## 검증
- 로컬 서버로 띄웠는가? (`file://` 아님)
- 콘솔 에러를 수집했는가?
- 모든 화면을 375px과 1440px에서 캡처했는가?
- Happy Path를 **클릭으로** 끝까지 수행했는가?
- Default 외 상태를 실제로 띄워봤는가?
- 서버를 종료했는가?

## 실행할 수 없는 경우
브라우저 도구를 사용할 수 없는 환경(Codex 등)에서는 이 Playbook을 생략하고,
**리포트에 "실행 검증 미수행"을 명시한다.** 판정은 코드 검토 기준으로만 내리되,
`Pass` 판정에 "실행 미검증" 단서를 붙인다. 검증하지 않은 것을 검증한 것처럼 기록하지 않는다.
