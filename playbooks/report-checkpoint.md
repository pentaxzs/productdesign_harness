# Skill: 체크포인트 보고

## 목적
각 Agent가 일을 마칠 때마다 **멈춰서** 무엇을 만들었는지 보여주고, 어떻게 진행할지 묻는다.

> 파이프라인이 말없이 끝까지 달리면, 잘못된 전제로 만든 결과물을 마지막에야 발견한다.
> Phase 1의 Screen Spec이 틀리면 이후 모든 Phase가 함께 틀린다.
> **되돌리는 비용이 묻는 비용보다 훨씬 크다.**

## 사용하는 Agent
- 모든 Agent (Planner, Wireframe, Prototype, Critic) — 각자 작업을 마친 직후

---

## 기본 동작: 멈춘다

체크포인트에서는 **기본적으로 멈추고 사용자에게 묻는다.**
사용자가 "끝까지 진행"을 고르기 전까지 계속 묻는다.

| 상태 | 동작 |
|------|------|
| **기본** | 각 체크포인트에서 요약을 보여주고 **AskUserQuestion으로 멈춘다** |
| 사용자가 "끝까지 진행"을 선택한 뒤 | 이후 체크포인트는 **요약만 출력하고 멈추지 않는다** |
| `$ARGUMENTS`에 `--auto`가 있으면 | 처음부터 멈추지 않는다 (요약은 계속 출력) |

**멈추지 않게 된 뒤에도 요약은 매번 출력한다.** 생략하면 침묵하는 파이프라인이 된다.

### 멈추지 않는 예외
- **Refine (Phase 5)** — 어느 상태에서도 멈추지 않는다. 고칠 것이 이미 명확하므로 물을 필요가 없다.
  각 회차마다 보고하지도 않는다. **최종 판정이 날 때 한 번만** 보고한다.

---

## 출력 형식

```markdown
### ✅ Phase N — <Agent 이름> 완료

| 산출물 | 내용 |
|--------|------|
| `경로/파일.md` | 한 줄 요약 (개수·핵심 수치 포함) |

**핵심 결정**
- 이 Phase에서 내린 판단 중 되돌리기 어려운 것 1~3개

**다음**: Phase N+1 — <무엇을 할지 한 줄>
```

그 다음 AskUserQuestion으로 묻는다.

### 작성 규칙
- **산출물 표에 숫자를 넣는다.** "화면 목록" ❌ → "화면 7개, 막다른 화면 0" ✅
  숫자가 있어야 사용자가 의도와 다른 것을 즉시 알아챈다.
- **핵심 결정**에는 "그냥 한 일"이 아니라 **다르게 할 수도 있었던 선택**을 적는다.
- 파일 내용을 그대로 붙여넣지 않는다. 경로를 알려주고 요약만 쓴다.
- 폴백이 작동했으면(예: Figma 미사용) **그 사실을 산출물 표에 적는다.**

---

## 질문 형식

AskUserQuestion으로 **하나**만 묻는다.

**질문**: `Phase N 결과로 진행할까요?`

**선택지** (순서 고정):

| # | 라벨 | 설명 | 선택 시 |
|---|------|------|---------|
| 1 | **다음 단계 진행** | 다음 Phase로 가고, 그 단계가 끝나면 다시 묻는다 | Phase N+1 실행 → 다시 체크포인트 |
| 2 | **끝까지 진행** | 남은 Phase를 묻지 않고 끝까지 진행한다. 각 단계 요약은 계속 보여준다 | 이후 모든 체크포인트에서 멈추지 않음 |
| 3 | **〈이 Phase에서 바꿀 만한 것〉** | 구체적으로 무엇을 어떻게 바꿀지 | 해당 Phase 재실행 → 다시 체크포인트 |
| 4 | **여기서 멈춤** | 산출물만 남기고 종료 | 파이프라인 종료, 산출물 위치 안내 |

3번은 **이 Phase에서 실제로 바꿀 수 있는 것**이어야 한다. 다음 Phase의 일을 미리 묻지 않는다.
바꿀 만한 것이 둘 이상 뚜렷하면 3번과 4번 사이에 하나 더 넣어도 된다 (최대 4개 선택지).

사용자가 2번을 고르면 **그 사실을 한 줄로 확인하고** 계속한다.
예: `끝까지 진행합니다. 각 단계 요약은 계속 보여드리고 멈추지 않습니다.`

---

## Phase별 보고 내용

| Phase | Agent | 산출물 표에 반드시 넣을 것 | 3번 선택지 예 |
|-------|-------|--------------------------|--------------|
| 1 | Planner | Key Scenarios 개수, 화면 개수, 막다른 화면 0 여부, checklist Part A 생성 여부, Figma 사용/폴백 | 화면 범위 조정 / 시나리오 추가·삭제 |
| 2 | Wireframe | 와이어프레임 화면 수, Mobile/Desktop 쌍 여부, Figma 사용/폴백 | 특정 화면 레이아웃 다시 |
| 3 | Prototype | 생성 파일, 구현 화면 수, 상태 제어 쿼리 구현 여부 | 목업 데이터 양·성격 조정 |
| 4 | Critic | **판정(Pass/Revise)**, 실행 검증 수행 여부, 콘솔 에러 수, Critical/Major/Minor 건수 | 특정 지적 사항 무시하고 Pass 처리 |
| 5 | (Refine) | 회차, 수정한 ID 목록, 재검증 결과 | — (멈추지 않음) |

Phase 4에서 판정이 **Revise**면 선택지를 다르게 둔다:
1. **수정 진행** (권장) — Phase 5로
2. **지적 사항 확인만 하고 멈춤**
3. **특정 이슈는 무시하고 Pass 처리**

---

## Output
사용자에게 보여주는 요약 + 질문 (파일로 저장하지 않는다)

## 검증
- 산출물 표의 각 행에 구체적 숫자나 상태가 있는가?
- "다음"이 한 줄로 명확한가?
- 선택지 1번이 "다음 단계 진행", 2번이 "끝까지 진행"인가?
- 3번이 이 Phase에서 실제로 바꿀 수 있는 것인가?
- Critic 체크포인트에 판정(Pass/Revise)이 포함되었는가?
- 사용자가 "끝까지 진행"을 고른 뒤에도 요약은 계속 출력하는가?
