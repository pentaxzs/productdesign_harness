# Skill: 체크포인트 보고

## 목적
각 Agent가 일을 마칠 때마다 **무엇을 만들었고 다음에 무엇을 할지**를 한 번에 보여준다.
사용자가 파이프라인 중간에 방향을 바꿀 수 있는 지점을 만드는 것이 목적이다.

> 파이프라인이 말없이 끝까지 달리면, 잘못된 전제로 만든 결과물을 마지막에야 발견한다.
> Phase 1의 Screen Spec이 틀리면 이후 모든 Phase가 함께 틀린다.

## 사용하는 Agent
- 모든 Agent (Planner, Wireframe, Prototype, Critic) — 각자 작업을 마친 직후

---

## 모드

| 모드 | 동작 | 언제 |
|------|------|------|
| **auto** (기본) | 요약과 선택지를 **보여주고 멈추지 않고** 다음 Phase로 진행 | 기본값. 전체를 한 번에 돌릴 때 |
| **confirm** | 각 체크포인트에서 **답변을 받을 때까지 멈춤** | `--confirm` 이 입력에 포함될 때 |

`$ARGUMENTS`에 `--confirm`이 있으면 confirm 모드, 없으면 auto 모드다.
`/wire`는 시작 시 어느 모드인지 사용자에게 한 줄로 알린다.

**auto 모드에서도 선택지는 반드시 출력한다.** 사용자가 읽고 끼어들 수 있어야 한다.
선택지를 생략하면 auto 모드는 그냥 침묵하는 파이프라인이 된다.

### confirm 모드에서도 멈추지 않는 경우
- Critic이 **Revise** 판정을 내렸을 때 → Refine은 자동으로 진행한다. 고칠 것이 명확하므로 물을 필요가 없다.
- Refine 각 회차 → 멈추지 않는다. 최종 판정이 나올 때 한 번만 보고한다.

---

## 출력 형식

```markdown
### ✅ Phase N — <Agent 이름> 완료

| 산출물 | 내용 |
|--------|------|
| `경로/파일.md` | 한 줄 요약 (개수·핵심 수치 포함) |

**핵심 결정**
- 이 Phase에서 내린 판단 중 되돌리기 어려운 것 1~3개

**다음**: Phase N+1 — <무엇을 할지 한 줄>

**바꾸려면**
1. <이 Phase 산출물에서 가장 바꿀 법한 것>
2. <두 번째>
3. 여기서 멈추고 결과물만 확인
```

### 작성 규칙
- **산출물 표에 숫자를 넣는다.** "화면 목록" ❌ → "화면 7개, 막다른 화면 0" ✅
  숫자가 있어야 사용자가 의도와 다른 것을 즉시 알아챈다.
- **핵심 결정**에는 "그냥 한 일"이 아니라 **다르게 할 수도 있었던 선택**을 적는다.
- **바꾸려면** 선택지는 2~4개. 이 Phase에서 실제로 바꿀 수 있는 것만 적는다.
  다음 Phase의 일을 미리 묻지 않는다.
- 파일 내용을 그대로 붙여넣지 않는다. 경로를 알려주고 요약만 쓴다.
- 폴백이 작동했으면(예: Figma 미사용) **그 사실을 산출물 표에 적는다.**

---

## Phase별 보고 내용

| Phase | Agent | 산출물 표에 반드시 넣을 것 |
|-------|-------|--------------------------|
| 1 | Planner | Key Scenarios 개수, 화면 개수, 막다른 화면 0 여부, checklist Part A 생성 여부, Figma 사용/폴백 |
| 2 | Wireframe | 와이어프레임 화면 수, Mobile/Desktop 쌍 여부, Figma 사용/폴백 |
| 3 | Prototype | 생성 파일, 구현한 화면 수, 상태 제어 쿼리 구현 여부 |
| 4 | Critic | **판정(Pass/Revise)**, 실행 검증 수행 여부, 콘솔 에러 수, Critical/Major/Minor 건수 |
| 5 | (Refine) | 회차, 수정한 ID 목록, 재검증 결과 |

## confirm 모드 질문 형식

AskUserQuestion으로 묻는다. 질문은 **하나**만 한다.

- 질문: `Phase N 결과로 진행할까요?`
- 선택지:
  1. `계속 진행` — 다음 Phase로 (권장을 기본 첫 번째에 둔다)
  2. `<이 Phase에서 바꿀 만한 것 1>`
  3. `<바꿀 만한 것 2>`
  4. `여기서 멈춤` — 산출물만 남기고 종료

사용자가 수정을 선택하면 **해당 Phase를 다시 실행**하고, 체크포인트를 한 번 더 보고한다.

---

## Output
사용자에게 보여주는 요약 (파일로 저장하지 않는다)

## 검증
- 산출물 표의 각 행에 구체적 숫자나 상태가 있는가?
- "다음"이 한 줄로 명확한가?
- "바꾸려면" 선택지가 이 Phase에서 실제로 바꿀 수 있는 것인가?
- auto 모드에서 선택지를 생략하지 않았는가?
- Critic 체크포인트에 판정(Pass/Revise)이 포함되었는가?
