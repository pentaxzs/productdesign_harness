# Playbook: 요구사항 분석

## 목적
사용자의 요청에서 Goal, 필요한 정보, 분기 조건, Edge Case를 추출한다.

## 전제 조건
- `playbooks/discover-context.md` (Discovery)가 완료되어 `context/product-context.md`의 필수 항목이 채워져 있어야 한다.
- Discovery가 완료되지 않았으면 이 Playbook을 실행하지 않고 Discovery를 먼저 수행한다.

## 사용하는 Agent
- Planner Agent (주 사용)
- Critic Agent (요구사항 충족 점검 시 참조)

## 절차

### 1. Goal 추출
사용자의 요청에서 핵심 목표를 문장으로 정리한다.
- "사용자는 [무엇]을 하고 싶다"
- 하나의 요청에 여러 Goal이 있으면 분리한다.

### 2. 사용자 정보 파악
사용자가 이미 알고 있는 정보와 모르는 정보를 구분한다.
- 알고 있음: 자신의 소비 패턴, 원하는 혜택 종류
- 모름: 어떤 카드가 있는지, 어떤 카드가 자신에게 맞는지

### 3. 필요한 질문 도출
서비스가 사용자에게 물어야 하는 질문을 정리한다.
- 어떤 정보를 입력받아야 추천/검색이 가능한가?
- 질문의 순서는 무엇이 자연스러운가?

### 4. 분기 조건 정리
사용자의 선택이나 상황에 따라 달라지는 경로를 정리한다.
- 검색 vs AI 추천 선택
- 검색 결과 있음 vs 없음
- 카드 비교 선택 여부

### 5. Edge Case 식별
비정상적이거나 예외적인 상황을 목록화한다.
- 검색 결과가 0건인 경우
- AI 추천이 실패한 경우
- 비교할 카드를 1개만 선택한 경우
- 네트워크 오류

## Output 형식
```markdown
## 요구사항 분석

### Goals
1. [Goal 1]
2. [Goal 2]

### 사용자가 아는 것 / 모르는 것
| 알고 있음 | 모름 |
|----------|------|
| ... | ... |

### 서비스가 물어야 할 질문
1. [질문] — [이유]

### 분기 조건
1. [조건] → [경로 A] / [경로 B]

### Edge Cases
1. [상황] — [대응 방법]
```
