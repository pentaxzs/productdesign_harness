# Skill: Screen Spec 작성

## 목적
User Flow에서 필요한 Screen을 도출하고, 각 Screen의 상세 Spec을 작성한다.

## 사용하는 Agent
- Planner Agent (주 사용)
- Wireframe Agent (화면 구현 시 참조)
- Critic Agent (충족 여부 점검 시 참조)

## 절차

### 1. Screen 목록 도출
User Flow의 모든 단계에서 필요한 화면을 추출한다.
- 동일한 화면이 여러 Flow에서 등장하면 하나로 합친다.
- 상태만 다른 경우(검색 결과 있음/없음)는 같은 화면의 다른 상태로 처리한다.

### 2. Screen 간 관계 정리
```
[진입 화면] → [중간 화면] → [목적 화면]
```

> 예시 (카드 추천 서비스):
> ```
> [홈] → [검색 결과] → [카드 상세]
> [홈] → [AI 추천] → [추천 결과] → [카드 상세]
> [검색 결과 / 추천 결과] → [카드 비교]
> ```

### 3. Screen Spec 작성
각 Screen에 대해 다음을 정의한다:

```markdown
## Screen: [이름]

### 목적
이 화면이 존재하는 이유. 한 문장.

### 진입 경로
- [어디서] → [어떤 행동으로] 이 화면에 도달

### 핵심 정보 (우선순위 순)
1. [가장 중요한 정보]
2. [두 번째 정보]
3. ...

### 사용자 액션
- [액션 1] → [결과]
- [액션 2] → [결과]

### Primary CTA
[버튼 텍스트] → [다음 화면/행동]

### 상태
| 상태 | 설명 |
|------|------|
| Default | [기본 상태 설명] |
| Empty | [데이터 없을 때] |
| Loading | [로딩 중일 때] |
| Error | [오류 발생 시] |

### 이동 경로
- → [다음 화면 1] (조건: ...)
- → [다음 화면 2] (조건: ...)
- ← [이전 화면] (뒤로가기)

### 필요한 UI 요소
- [요소 역할] — [무엇을 하는가]
- [요소 역할] — [무엇을 하는가]
```

> **컴포넌트 이름을 쓰지 않는다.** "Card Grid Image" ❌ → "시각 위주 항목 목록" ✅
> Screen Spec은 *화면에 무엇이 필요한가*를 적는 문서다. *무엇으로 만드는가*는
> Phase 2의 `map-components.md`가 정한다. 디자인 시스템은 Phase 2에서 바뀔 수 있으므로,
> 여기에 특정 DS의 컴포넌트 이름을 박으면 그 전제가 Phase 1 산출물에 남는다.

## Output
`specs/screens.md`에 작성

## 검증
- User Flow의 모든 화면이 Spec으로 존재하는가?
- 각 Screen에 명확한 목적이 있는가?
- 각 Screen에 Primary CTA가 하나만 있는가?
- 진입할 수 없는 Screen이 없는가?
- 빠져나갈 수 없는 Screen이 없는가?
