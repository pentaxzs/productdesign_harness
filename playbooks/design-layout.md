# Skill: 레이아웃 설계

## 목적
각 화면의 정보 계층과 레이아웃 구조를 설계한다.

## 사용하는 Agent
- Wireframe Agent (주 사용)

## 절차

### 1. 정보 우선순위 결정
Screen Spec의 "핵심 정보" 순서를 시각적 우선순위로 변환한다:
- 1순위: 최상단, 가장 큰 크기, 가장 높은 대비
- 2순위: 그 아래, 적절한 크기
- 부가 정보: Accordion이나 별도 섹션으로

### 2. CTA 배치
- Mobile: 콘텐츠 직후 또는 화면 하단 고정 (sticky)
- PC: 콘텐츠 우측 또는 콘텐츠 직후
- Primary CTA는 시각적으로 가장 강조 (Button Primary)
- Secondary 액션은 Button Secondary 또는 텍스트 링크

### 3. 레이아웃 그리드
- Mobile (375px): 단일 컬럼, 좌우 패딩 16px
- Tablet (768px): 2컬럼 가능, 좌우 패딩 24px
- PC (1440px): 최대 너비 1200px 중앙 정렬, 2~3컬럼

### 4. 섹션 구조
각 화면을 섹션으로 나눈다. 해당 없는 섹션은 생략한다.
```
[Header]          ← 공통
[진입/입력 영역]   ← Hero, 검색, 질문 등 (해당 시)
[조건 영역]        ← 필터, 탭, 정렬 (해당 시)
[콘텐츠 영역]      ← 이 화면의 본문
[CTA 영역]
[Footer]          ← 공통
```

### 5. 간격 체계
`context/design-system.md`의 Spacing 토큰을 사용한다. 아래는 토큰이 없을 때의 기본값이다.

- 섹션 간: 48px (mobile) / 64px (PC)
- 컴포넌트 간: 16px ~ 24px
- 컴포넌트 내부: 8px ~ 16px
- **4px 기반 스케일 준수** — 임의의 값(예: 15px, 30px)을 쓰지 않는다

## Output
`specs/layouts.md`에 각 화면의 레이아웃 구조도를 작성한다.

> 다음 단계(`build-wireframe-figma.md` 또는 `build-prototype-html.md`)가 이 파일을 읽는다.
> 세션 안에서만 들고 있으면 `/wireframe`을 단독 실행했을 때 레이아웃 근거가 사라진다.

```
## Layout: [Screen 이름]

### Mobile (375px)
┌─────────────┐
│   Header    │
├─────────────┤
│   진입 영역  │
├─────────────┤
│   조건 영역  │
├─────────────┤
│  콘텐츠 항목 │
│  콘텐츠 항목 │
├─────────────┤
│   Footer    │
└─────────────┘

### PC (1440px)
┌───────────────────────────┐
│          Header           │
├───────────────────────────┤
│         진입 영역          │
├────────┬──────────────────┤
│ 조건   │   콘텐츠 그리드   │
│ 영역   │   콘텐츠 그리드   │
├────────┴──────────────────┤
│          Footer           │
└───────────────────────────┘
```

### 상태별 레이아웃
Default 외에 레이아웃이 달라지는 상태가 있으면 함께 기록한다.
(예: Empty State는 콘텐츠 영역 대신 안내 + CTA)

## 검증
- `specs/screens.md`의 모든 화면에 레이아웃이 있는가?
- 화면마다 Mobile과 PC 구조가 **쌍으로** 있는가?
- Primary CTA가 화면당 하나이고, Mobile/PC 중 한쪽에만 배치되는가?
- 간격이 4px 스케일을 따르는가?
