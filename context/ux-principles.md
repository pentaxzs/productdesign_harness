# UX Principles

이 하네스에서 모든 Agent가 반드시 따라야 하는 UX 원칙입니다.
**제품에 중립적인 기본 원칙**이며, 팀이나 제품의 성격에 맞게 수정해서 쓰는 것을 전제로 합니다.

> 수정 가이드: 원칙은 7개 내외로 유지하세요. 너무 많으면 Critic이 우선순위를 판단하지 못합니다.
> 제품 고유의 원칙이 필요하면 아래 "제품별 원칙"에 추가합니다.

---

## 1. 명확한 정보 계층 (Clear Information Hierarchy)
- 사용자의 의사결정에 가장 중요한 정보가 먼저 보여야 한다.
- 부가 정보는 접기/펼치기 또는 상세 화면에서 제공한다.
- 한 화면에 너무 많은 정보를 보여주지 않는다.

## 2. 최소 단계 (Minimum Steps)
- 핵심 Task를 완료하기까지의 단계를 최소화한다.
- 입력에 대한 결과는 가능한 한 즉시 보여준다.
- 핵심 기능은 회원가입이나 로그인 없이 체험할 수 있게 한다.

## 3. 신뢰감 (Trust)
- 보여주는 정보가 정확하고 최신이라는 인상을 준다.
- 과장된 표현이나 광고성 문구를 지양한다.
- 비교·평가 화면에서는 모든 대상에 동일한 기준을 적용한다.
- 자동 생성된 결과는 그 근거를 함께 보여준다.

## 4. 일관된 패턴 (Consistent Patterns)
- 동일한 유형의 정보는 동일한 방식으로 표현한다.
- 목록 → 상세 → 비교로 이어지는 화면들의 정보 구조가 일관되어야 한다.
- Design System 컴포넌트를 우선 사용하고, 커스텀 UI를 최소화한다.

## 5. 사용자 주도권 (User Control)
- 자동화·추천·AI 기능은 제안하되 강요하지 않는다.
- 시스템이 내린 결정을 사용자가 수정하거나 되돌릴 수 있어야 한다.
- 능동적 탐색(검색·필터)과 수동적 발견(추천·피드)을 자연스럽게 연결한다.

## 6. 모든 상태를 고려 (Handle All States)
- **Empty State**: 아직 데이터가 없을 때, 결과가 0건일 때, 아무것도 선택하지 않았을 때
- **Error State**: 네트워크 오류, 처리 실패, 잘못된 입력
- **Loading State**: 데이터 로딩 중, 처리에 시간이 걸릴 때
- 각 상태에서 사용자가 다음에 무엇을 해야 하는지 안내한다.

## 7. 반응형 우선 (Responsive First)
- Mobile에서 먼저 설계하고, PC로 확장한다. (기준: 375px → 1440px)
- 터치 타겟은 최소 44px을 유지한다.
- PC에서는 공간을 활용하되, 정보 밀도를 적절히 조절한다.
